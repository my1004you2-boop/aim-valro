# 헤드라인 에임 트레이너 — 설계 문서 (프로토타입)

작성일: 2026-10-29

## 1. 의도와 이유

사용자는 발로란트를 하면서 **헤드를 맞추는 것**이 어렵다. 특히 적이 **거리별·높낮이별**로 다르게 나타날 때 그렇다. 문제는 두 가지다(사용자 확인).

1. **조준선 위치(크로스헤어 플레이스먼트)** — 적이 나타나기 전에 조준선이 머리 높이에 있지 않아서 크게 옮겨야 한다.
2. **마지막 미세 조정** — 거의 맞았는데 마지막에 머리를 빗나간다.

Aim Lab과 비슷한 성격의 **개인용 설치형 연습 프로그램**을 만든다. 이 두 문제에 집중하되, 사용자 요청에 따라 **발로란트 환경과 최대한 비슷하게** 만든다(이동, 총기 특성, 봇의 A/D 피킹). 이번 범위는 **프로토타입**이다. 사용자가 직접 써 본 뒤 자신만의 프리셋을 정할 예정이므로, 대부분의 수치를 설정이나 데이터 파일에서 바꿀 수 있어야 한다.

## 2. 목표

- 발로란트와 **같은 마우스 회전량, 시야각, 조준선**으로 연습한다.
- 플레이어가 **이동·걷기·앉기·점프**를 할 수 있고, 발로란트처럼 **이동 중 사격이 부정확**하다.
- 총기마다 **데미지, 초탄 퍼짐, 연사 속도, 연속 사격 퍼짐/반동, 탄창·재장전**이 반영된다.
- 봇이 벽 뒤에서 **죽을 때까지 무작위로 A/D 피킹**(숏 피킹 / 와이드 피킹)을 한다.
- 결과를 **거리별 × 높이별**로 보여 주어 약한 상황을 바로 알 수 있다.
- 바탕화면 아이콘으로 실행하는 **윈도우 설치형** 프로그램이다(브라우저가 아님 — 사용자 선호).

## 3. 비목표 (이번 프로토타입에서 하지 않음)

- 프리셋 저장/불러오기 UI — 사용자가 나중에 정한다. 단, 설정 구조는 "프리셋 = 이름 붙인 설정 묶음 하나"로 쉽게 확장되게 만든다.
- 조준선 코드 입력 화면 — 추후 다른 사용자를 위해 제공할 예정이다.
- 샷건과 저격총(Shorty, Bucky, Judge, Marshal, Outlaw, Operator), 그리고 조준경(우클릭 줌/ADS). 산탄과 스코프 처리가 필요해서 다음 단계로 미룬다.
- 봇의 반격, 스킬(요원 능력), 칼 들기, 총기 교체(한 판에 총 하나).
- 기록 히스토리 화면이나 그래프. 세션 결과를 파일로 남기는 것까지만 한다.
- 발로란트 맵, 특정 요원, 로고 같은 **실제 게임 자산이나 브랜딩 재현**. 맵 구조나 요원 생김새를 그대로 복제하지 않는다. 대신 **체형·히트박스·맵 설계 원칙** 같은 실전 감각에 영향을 주는 부분을 최대한 비슷하게 맞춘다(10장, 11장).
- 멀티플레이, 온라인 기능, 자동 업데이트.

## 4. 반목표 (돌아가더라도 이렇게 되면 실패)

- **감도, 이동, 사격 정확도가 게임과 다르게 느껴지는 것.** 잘못된 감각을 익히게 되면 연습이 오히려 해가 된다.
- **입력 지연과 프레임 끊김.** 마우스 가속이 들어가거나 프레임이 165fps 아래로 떨어지는 것.
- 머리가 아닌 곳에 맞은 것을 헤드처럼 보이게 하는 것.

## 5. 확정된 사항과 제약

### 기술 (Claude의 결정, 사용자가 반대하지 않음)
- **Electron + Three.js**, 윈도우 11 대상. 개발 PC에 Node 24, npm 11이 설치되어 있다.
- 설치 파일(또는 포터블 exe)을 만들어 바탕화면 바로가기로 실행한다.

### 사용자 환경 (사용자 값)
- 마우스 DPI **1600**, 발로란트 감도 **0.194** (eDPI 약 310, 한 바퀴에 약 42cm).
- 모니터 **1920×1080, 16:9, 165Hz**.

### 감도
- 발로란트 회전 공식: **회전(도) = 마우스 카운트 × 0.07 × 감도**. 가로와 세로에 같은 배율을 쓴다.
- DPI는 회전 계산에 들어가지 않는다(카운트 기준이기 때문). cm/360 표시에만 쓴다.
- 마우스 입력은 Pointer Lock의 `unadjustedMovement: true`(원본 입력, 윈도우 가속 무시)로 받는다. 지원되지 않으면 경고를 띄운다.
- 감도 계산과 FOV 환산은 자동 테스트로 확인한다.

### 시야
- 가로 시야각 **103도**(발로란트 고정값). Three.js는 세로 FOV를 쓰므로 화면 비율에서 환산한다. 16:9에서는 세로 약 70.5도다.
- 16:9보다 좁은 화면에서는 발로란트처럼 16:9 기준 세로 FOV를 유지한다(다른 사용자 대비).
- 기본은 전체화면 실행이다.

### 성능
- 프레임 제한과 수직동기를 끈다(Electron 스위치 `disable-frame-rate-limit`, `disable-gpu-vsync`). 165fps 이상을 안정적으로 유지해야 하며, FPS를 화면에 작게 표시한다.

### 조준선 (사용자 지정 코드로 고정)
- 코드: `0;s;1;P;c;5;o;0.101;f;0;0t;1;0l;2;0v;2;0o;1;0a;1;0f;0;1b;0;S;s;1.002`
- 해석(Claude의 판단):
  - 색: 시안(#00FFFF, 색 번호 5)
  - 중앙 점: 없음
  - 테두리: 켬, 두께 1, 불투명도 0.101
  - 안쪽 선: 두께 1, 가로 길이 2, 세로 길이 2, 간격 1, 불투명도 1
  - 바깥 선: 끔
  - 사격 오차 표시: 끔
  - `S;s;1.002`는 저격 조준경 관련 값이라 이번에는 무시한다.
- 구현은 **발로란트 조준선 코드를 해석하는 모듈**로 만들고, 위 코드를 기본값으로 넣는다. 1080p 화면에서 발로란트와 같은 픽셀 크기로 그린다. 나중에 입력 화면을 붙일 때 이 모듈을 그대로 다시 쓴다.

## 6. 발로란트 수치 조사 원칙

이동 속도, 점프, 이동 중 부정확성, 총기 수치, 방어구 규칙은 **구현할 때 웹에서 최신 패치 값을 조사해서** 데이터 파일(`data/movement.json`, `data/weapons.json`, `data/armor.json` 같은 형태)에 넣는다. 각 파일 맨 위에 출처와 패치 버전을 적는다. 패치가 바뀌면 이 파일들만 고치면 된다. 공개된 정확한 값이 없는 항목(반동 패턴 등)은 근사값을 쓰고, 파일에 "근사값"이라고 표시한다.

## 7. 플레이어

- 조작: **WASD 이동, Shift 걷기, Ctrl 앉기(누르는 동안), Space 점프, 마우스 왼쪽 사격, R 재장전, Esc 일시정지**. 기본 키는 발로란트 기본값을 따른다.
- 달리기·걷기·앉아 걷기 속도, 가속과 감속, 점프 높이, 중력, 들고 있는 총에 따른 이동 속도 배율을 발로란트 수치로 맞춘다. **카운터 스트레이핑**(반대 키를 눌러 빨리 멈추는 것)이 게임처럼 동작해야 한다.
- 앉으면 눈높이가 낮아지고, 앉아 있는 동안 사격 정확도가 좋아진다(발로란트 수치).
- 계단과 경사로를 올라갈 수 있고, 박스 위로 점프해서 올라갈 수 있다. 벽을 통과할 수 없다.
- 이동 범위는 연습장 안으로 제한한다. 한 판을 시작할 때 정해진 시작 위치에서 출발한다.

## 8. 총기

- 대상(Claude의 결정): 권총 Classic, Ghost, Sheriff, Frenzy / 기관단총 Stinger, Spectre / 소총 Bulldog, Guardian, Phantom, Vandal / 기관총 Ares, Odin. 기본은 **Vandal**이다.
- 총기마다 데이터 파일에 다음 값을 둔다(모두 발로란트 최신 값).
  - 머리·몸·다리 데미지, 거리 구간별 감소
  - 연사 속도, 자동/반자동 여부(자동 총기는 누르고 있으면 연사됨)
  - 서 있을 때 첫 발 퍼짐, 앉았을 때 퍼짐
  - 걷기·달리기·공중 사격 시 퍼짐(이동 중 부정확성)
  - 연속 사격 시 퍼짐 증가와 회복 시간(같은 간격으로 탭하면 다시 정확해지는 시간)
  - 반동: 화면이 튀는 정도와 탄이 위·옆으로 올라가는 경향. 정확한 패턴이 공개되어 있지 않으면 근사값을 쓴다.
  - 탄창 크기, 재장전 시간, 장착 시 이동 속도 배율
- 탄은 조준점 둘레의 원뿔 안에서 무작위로 퍼진다. 조준점이 머리 정중앙이어도 퍼짐 때문에 빗나갈 수 있다.
- 탄창이 비면 자동으로 재장전한다(발로란트와 같음).
- 결과에 따로 세는 항목:
  - **"조준은 머리였는데 퍼짐 때문에 빗나간 발"** — 조준 문제와 총기 문제를 구분하기 위해서다.
  - **"움직이면서 쏜 발"** — 이동 중 사격 습관을 확인하기 위해서다.

## 9. 판정 방식 (사용자 요청: 매번 선택)

연습을 시작할 때마다 **모드, 총기, 판정 방식, 방어구**를 고른다. 시작 화면은 마지막 선택을 기억한다.

1. **헤드 전용**: 머리를 맞혀야 봇이 쓰러진다. 몸이나 다리에 맞은 것은 기록만 하고, 데미지는 표시만 한다.
2. **처치**: 봇은 체력 100에 방어구(없음 / 경량 25 / 중량 50)를 가진다. 체력이 0이 되면 쓰러진다. 방어구가 데미지를 흡수하는 규칙은 최신 게임 규칙을 따른다. 결과에 처치까지 걸린 시간, 발 수, 원탭(한 발 처치) 비율을 보여 준다.

## 10. 연습장

- 바닥, 벽, 박스, 계단, 2층 발판, 아래로 내려간 구역으로 이루어진 **단순하지만 실전 같은 공간**이다. 높낮이 차이와 다양한 거리(5–50m)가 핵심이다.
- 봇이 피킹할 수 있는 **엄폐물 지점**(벽 끝, 박스 옆, 문틀 등)을 여러 거리와 높이에 배치한다. 각 지점은 봇이 숨는 위치와 피킹하는 방향(왼쪽/오른쪽)을 가진다.
- 색과 디자인은 어둡고 깔끔한 연습장 느낌이다(빌더에게 맡김).

### 실전 맵 (사용자 요청: 저작권을 해치지 않는 범위에서 발로란트 맵과 최대한 비슷하게)
- 기존 발로란트 맵의 배치를 복제하지 않는 **독자적인 맵**이다. 대신 발로란트 맵의 **설계 원칙**을 따른다.
  - 공격 진영 쪽 출발 지역, 수비 진영 쪽 출발 지역, 사이트 2개(A, B), 미드 구역.
  - 사이트로 들어가는 좁은 입구(초크), 메인 통로, 짧은 연결 통로.
  - 사이트 안의 박스와 엄폐물, 높은 자리(헤븐)와 낮은 자리, 계단과 짧은 경사로.
  - 실제 교전처럼 가까운 거리(5–15m)부터 긴 직선 통로(40–50m)까지 다양한 거리가 나온다.
  - 이동 속도 기준으로 출발 지역에서 사이트까지 걸리는 시간이 발로란트와 비슷하다(약 15–25초 정도, 조사 후 조정).
- 생김새는 단순한 도형과 단색 재질로 만든다(사용자 동의). 맵 레이아웃은 데이터 파일로 만들어서 나중에 맵을 추가할 수 있게 한다.

## 11. 봇

- **생김새 (사용자 요청: 최대한 발로란트 요원 형태)**: 특정 요원을 복제하지 않는 **독자 디자인의 전술 요원 인간형 모델**이다(사용자 동의).
  - 체형과 비율(키, 머리 높이, 머리 크기, 어깨 폭)은 발로란트 요원과 비슷하게 맞춘다. 실제 게임에서 머리가 있을 위치와 크기가 그대로 나오는 것이 핵심이다.
  - 총을 든 채 서 있는 자세, 앉은 자세, A/D로 움직일 때 몸이 기울고 다리가 움직이는 애니메이션이 있다.
  - 헬멧이나 후드 없이 머리 윤곽이 잘 보이는 형태로 만든다.
  - 모델은 직접 만들거나(코드로 조립하거나 Blender 등으로 제작) 상업 이용이 가능한 무료 라이선스 모델을 쓴다(빌더 판단). 라이선스를 `assets/LICENSES.md`에 기록한다.
- 판정은 **머리 / 몸 / 다리**로 나뉘고, 발로란트 요원 히트박스와 비슷한 형태와 크기다(키 약 1.8m, 머리 중심 높이 약 1.6m 근처, 조사 후 조정). 설정에서 바꿀 수 있다. 판정은 보이는 모델이 아니라 히트박스 기준이며, 애니메이션을 따라 움직인다.
- **피킹 방식 (사용자 요청)**: 벽 뒤에 숨어 있다가 **죽을 때까지 무작위로 A/D 피킹을 반복**한다.
  - **숏 피킹**: 머리와 어깨 정도만 잠깐 드러났다가 다시 들어간다.
  - **와이드 피킹**: 몸 전체가 드러날 만큼 크게 나왔다가 들어간다.
  - 피킹 방향(엄폐물 양쪽이 열려 있으면 좌우 모두), 숏/와이드 선택, 나와 있는 시간, 숨어 있는 시간, 방향을 바꾸는 타이밍을 매번 무작위로 정한다. 비율과 범위는 설정에서 바꿀 수 있다.
  - 봇은 발로란트 플레이어와 같은 이동 속도와 가감속으로 움직인다(실제 A/D처럼 보이게).
- 봇은 **반격하지 않는다**(Claude의 결정).
- 봇이 쓰러지면 잠깐 뒤(기본 0.5–1.5초) 다른 엄폐물 지점에서 다음 봇이 나타난다. 다음 지점은 플레이어의 **현재 위치 기준**으로 거리 구간 × 높이 구간이 고르게 섞이도록 고른다. 플레이어에게서 보이는 지점 중에서만 고른다.
- 다음 봇이 숨어 있는 엄폐물은 짧게 표시해서(예: 지점 테두리가 잠깐 빛남) 플레이어가 그 각을 잡을 수 있게 한다. 표시를 켜고 끄는 설정을 둔다.

## 12. 연습 모드

### 모드 1 — 피킹 대응 (기본 모드)
목적: 각을 잡고, 봇이 나오기 전에 조준선을 머리 높이에 두고, 피킹하는 봇의 머리를 맞히는 것.
- 위의 봇이 한 번에 한 명씩 나와서 죽을 때까지 피킹한다.
- 기록 항목:
  - **배치 오차**: 각 피킹에서 봇의 머리가 처음 보인 순간, 조준선과 머리 중심 사이의 세로·가로 각도 차이(도 단위, "머리 몇 개 분량"으로도 표시). 세로 오차가 핵심 지표다.
  - **처치 시간**: 봇이 처음 보인 순간부터 쓰러질 때까지의 시간.
  - 몇 번째 피킹에서 쓰러졌는지, 숏 피킹과 와이드 피킹 중 어느 쪽에서 쓰러졌는지, 발 수, 첫 발 결과.
- 한 판은 봇 N명(기본 30명)을 쓰러뜨리면 끝난다. 일시정지 메뉴에서 중간에 끝낼 수도 있다.

### 모드 2 — 미세 조정
목적: 머리 근처까지 온 조준선을 마지막에 정확히 붙이는 연습.
- 해당 거리·높이 구간의 공중에 작은 **시작 점**이 뜬다. 조준선을 시작 점에 0.3초 올려 두면, 시작 점에서 1–4도 떨어진 곳에 봇이 나타난다(바닥이나 발판 위에 선다). 세로 오프셋은 시작 점을 머리보다 위나 아래에 두어서 만든다.
- 이 모드에서 봇은 그 자리에 서 있거나, 설정에 따라 짧은 A/D를 한다(기본은 짧은 A/D).
- 기록: 나타난 순간부터 처치까지의 시간, 발 수, 첫 발 결과. 시간 제한(기본 1.5초)을 넘기면 실패다.
- 플레이어 이동은 이 모드에서도 가능하다.

### 모드 3 — 실전 연습 (사용자 요청: 맵을 돌아다니며 실전처럼)
목적: 실전 맵을 걸어 다니며 각을 확인하고, 피킹하는 봇을 먼저 정확히 맞히는 것.
- 실전 맵(10장)의 공격 출발 지역에서 시작한다. 공략할 사이트(A / B / 무작위)를 시작할 때 고른다.
- 맵 곳곳의 실전 자리(입구 옆, 박스 뒤, 헤븐, 긴 통로 끝 등)에 봇이 숨어 있다. 자리는 맵 데이터에 후보로 정의하고, 매 판 그중 일부에 무작위로 배치한다(기본 8–12명).
- 플레이어가 봇이 볼 수 있는 범위에 들어오면, 봇이 무작위 지연 후 숏 피킹이나 와이드 피킹을 시작해서 죽을 때까지 반복한다(11장과 같은 방식). 이 모드에서는 엄폐물 표시를 하지 않는다.
- **봇은 반격하지 않는다(사용자 확인).** 반격은 사용 후 개선 사항으로 남긴다.
- 사이트 안의 봇을 모두 쓰러뜨리거나, 모든 봇을 쓰러뜨리거나, 일시정지 메뉴에서 끝내면 판이 끝난다.
- 기록은 모드 1과 같다(배치 오차, 처치 시간, 거리·높이 구간, 숏/와이드 성적, 움직이며 쏜 발). 추가로 봇의 자리별 성적과 한 판에 걸린 총 시간을 기록한다.

### 만드는 순서 (사용자 확인)
1. 기반: 감도, 시야, 조준선, 이동, 총기, 판정
2. 사격장: 모드 1(피킹 대응), 모드 2(미세 조정)
3. 실전 맵과 모드 3

만든 뒤 사용자가 직접 쓰면서 개선하고 수정한다.

## 13. 거리·높이 구간

- 거리와 높이는 **쏜 순간 플레이어와 봇의 실제 위치**로 계산한다(플레이어가 움직이기 때문).
- 거리 구간(기본): 가까움 5–15m / 중간 15–30m / 멂 30–50m.
- 높이 구간(기본): 플레이어 발보다 봇 발이 1.5m 이상 낮으면 **아래**, ±1.5m 안이면 **같은 높이**, 1.5m 이상 높으면 **위**.
- 모든 구간 경계는 설정에서 바꿀 수 있다.

## 14. 결과

- 요약: **첫 발 헤드샷 비율(대표 지표, 가장 크게 표시)**, 전체 헤드샷 비율, 몸·다리 비율, 평균 처치 시간, 평균 세로·가로 배치 오차(모드 1), 퍼짐 때문에 빗나간 발 수, 움직이면서 쏜 발 수. 처치 판정이면 원탭 비율도 표시한다.
- **거리 구간 × 높이 구간 표(3×3)**: 칸마다 헤드샷 비율과 평균 처치 시간을 보여 주고, 가장 약한 칸을 강조한다.
- 모드 1 추가: 숏 피킹 대비 와이드 피킹 성적.
- 세션마다 결과를 앱 데이터 폴더에 JSON 파일로 저장한다(날짜, 모드, 총기, 판정 방식, 설정값, 발마다의 원본 기록).

## 15. 화면 흐름

1. **메인 메뉴**: 모드(피킹 대응 / 미세 조정 / 실전 연습), 총기, 판정 방식, 방어구, (실전 연습이면) 사이트 선택 → 시작. 설정, 종료. 현재 감도와 cm/360을 표시한다.
2. **연습 화면**: 3D 연습장, 조준선, 탄약 수, 남은 봇 수, 헤드샷 비율, FPS. `Esc`를 누르면 일시정지(계속 / 끝내고 결과 보기 / 메인으로).
3. **결과 화면**: 요약과 3×3 표, "다시 하기" / "메인으로".

## 16. 설정 (모두 저장되며, 나중에 프리셋의 기반이 된다)

- 감도: DPI, 발로란트 감도. cm/360 자동 표시.
- 시야: 가로 FOV(기본 103).
- 조준선: 코드 문자열로 저장(기본값은 사용자 코드, 입력 화면은 추후 제공).
- 키 설정: 기본은 발로란트 기본키. 이번에는 파일에서만 바꿀 수 있다.
- 한 판 봇 수(기본 30).
- 거리·높이 구간 경계, 각 구간 사용 여부.
- 봇 피킹: 숏/와이드 비율, 나와 있는 시간 범위, 숨어 있는 시간 범위, 다음 봇 대기 시간, 엄폐물 표시 켜기/끄기.
- 모드 2: 오프셋 각도 범위, 시간 제한, 봇 A/D 켜기/끄기.
- 봇 히트박스 크기, 머리·몸·다리 색.
- 소리: 사격음, 헤드/몸샷 효과음 켜기/끄기, 음량.
- 설정은 앱 데이터 폴더의 `settings.json`에 하나의 객체로 저장한다. 나중에 "프리셋 = 이름 붙인 설정 객체"로 확장한다.

## 17. Claude가 정한 사항 (사용자가 확인할 부분)

- Electron + Three.js 설치형.
- 조준선 코드의 해석(5장).
- 총기 범위: 샷건과 저격총은 제외, 기본 총기는 Vandal.
- 봇은 반격하지 않는다.
- 다음 봇의 엄폐물을 짧게 표시한다(끌 수 있음).
- 모드 2는 시작 점 방식이다.
- 높이 구간 경계는 ±1.5m다.
- 반동 패턴은 정확한 공개 데이터가 없으면 근사값을 쓴다.
- 대표 지표는 첫 발 헤드샷 비율이다.

- 프로젝트 구조, 코드 구성, 물리/충돌 처리 방식, 패키징 도구(electron-builder 등) 선택.
- 연습장의 구체적인 배치와 색감, UI 디자인.
- 효과음 제작 방법(간단한 합성음으로 충분).
- 검증 방법. 단, 감도·FOV 환산, 데미지·방어구 계산, 조준선 코드 해석은 자동 테스트로 확인할 것.
